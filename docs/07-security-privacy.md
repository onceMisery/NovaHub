# NovaHub 安全与隐私

## 1. 威胁模型

需要防御的主要风险：恶意或被攻陷的插件、畸形插件包、无限计算与内存消耗、权限逃逸、敏感信息泄漏、IPC 冒充、更新供应链攻击和本地数据被其他低权限进程读取。

MVP 不承诺抵御已获得管理员/root 权限或完全控制当前用户会话的攻击者，但必须遵循最小权限并减少可利用面。

## 2. 信任边界

```text
可信：签名的 NovaHub 主程序、Plugin Manager、数据库迁移
受限可信：Plugin Host 进程与 Wasmtime
不可信：所有第三方 WASM、插件资源、网络响应、导入包
外部系统：OS API、系统索引、凭据存储、更新源
```

来自插件和网络的数据必须在进入 UI、日志、文件系统或数据库前验证。

## 3. 插件沙箱

- WebAssembly Component 不继承宿主环境变量、stdio、目录或 Socket
- 不预开放通用 WASI；只链接 NovaHub 明确提供的 WIT 能力
- 每个插件独立 Store、内存限制、fuel/epoch、deadline 与资源表
- Host API 每次调用重新校验插件身份、权限和参数，而非只在安装时校验
- URL 规范化后匹配 HTTPS Origin，并对 DNS 重绑定、重定向和本地/保留地址进行防护
- 文件句柄由宿主生成且与插件绑定，路径字符串不能替代句柄
- View 输入进行深度、数量、长度、Markdown 和资源校验

## 4. 包与供应链

- 归档解压防路径穿越、符号链接逃逸、压缩炸弹和重复文件覆盖
- 清单、WASM 与资源全部包含在签名范围
- 插件发布者使用 Ed25519 密钥；市场阶段再增加身份验证和撤销机制
- 官方二进制生成 SBOM，依赖执行许可证和漏洞扫描
- CI 固定 Rust 工具链与关键依赖版本，发布从受保护标签产生
- 安装包校验失败一律拒绝，不提供“仍然安装”按钮；开发者模式是独立路径

## 5. 应用签名与更新

- Windows 二进制和安装包使用代码签名证书，更新校验签名与哈希
- macOS 使用 Developer ID、Hardened Runtime、Notarization 和 Stapling
- 更新元数据使用独立签名并防回滚到低于安全最低版本
- 下载到 staging 后校验、安装、健康检查，再切换版本
- 更新失败恢复旧版本；数据库迁移与应用更新要有兼容窗口

## 6. 本地数据保护

- 数据目录权限限定当前用户
- 剪贴板和插件 Secret 加密，密钥存系统凭据存储
- 崩溃报告和诊断包默认本地生成，发送前展示包含内容并允许删减
- 设置提供“暂停剪贴板”“清空历史”“删除全部本地数据”入口
- 卸载插件默认删除其本地存储、Secret、缓存、权限和索引
- 应用卸载器是否删除 NovaHub 全部用户数据必须由用户明确选择，不能隐式删除

## 7. 隐私策略

MVP 默认无遥测、无账号、无云端。若未来引入遥测：

- 必须显式选择加入
- 事件采用数据字典，不允许任意属性
- 不收集查询、剪贴板、文件名、插件表单内容或完整 URL
- 提供本机查看、导出和撤回
- 产品功能不能依赖用户同意遥测

## 8. 权限 UX

权限提示必须说明：插件是谁、请求什么能力、允许的具体范围、为什么需要、拒绝后哪些功能不可用。新增权限不能在静默更新中获得。

网络权限展示 Origin 列表；文件权限展示选定目录或文件；剪贴板读写分开。MVP 不提供永久“所有文件”权限。

## 9. 安全测试

- 插件包 fuzz、WIT 解码 fuzz、View/Markdown fuzz
- IPC 长度、认证、重放、乱序和断连测试
- SSRF、重定向、DNS 重绑定和 URL 规范化测试
- 文件句柄越权、符号链接和 TOCTOU 测试
- Wasmtime 超时、内存、资源表泄漏与大量会话压力测试
- 数据库损坏、迁移回滚、密钥缺失与凭据删除测试
- Windows/macOS 签名、权限和升级/降级测试

## 10. 响应与撤销

建立插件哈希和签名撤销列表，但 MVP 本地安装模式下只能在用户更新 NovaHub 或主动刷新安全元数据后生效。撤销后默认禁用插件并解释原因，不在未确认时删除用户外部文件。

严重宿主漏洞需要最低安全版本策略、发布公告和更新迁移路径。安全修复不得通过扩大云端依赖或收集更多用户数据实现。
