# NovaHub V1 热门能力与现代化体验方案

## 1. 决策摘要

NovaHub V1 采用“能力对标 + 迁移辅助”的平衡方案：以 NovaHub 原生能力覆盖 uTools 与 Raycast 中高频、可日常使用的工作流，同时提供配置、清单与数据迁移工具。V1 不运行两者的插件包，不复制其私有 API，也不引入 JavaScript/WebView 兼容运行时。

平台策略为 Windows 功能完整优先，macOS 保持同一领域契约、插件协议与官方 UI，并在首发阶段完成核心能力。任何平台差异都收敛在 `platform/windows` 与 `platform/macos`，不能进入插件 WIT 或 UI View 协议。

## 2. 首期范围选择

曾评估三种范围：

| 方案 | 数量 | 优点 | 主要代价 | 结论 |
|---|---:|---|---|---|
| 精简核心 | 8 项 | 最快验证架构 | 难以成为日常替代品 | 不采用 |
| **平衡版本** | **14 项** | 日常价值、风险与周期均衡 | 需要分阶段交付 | **采用** |
| 全面覆盖 | 20+ 项 | 功能列表更完整 | 稳定性、平台差异和测试面失控 | 不采用 |

V1 的“支持”指用户能在 NovaHub 中完成同类任务，不代表兼容 uTools/Raycast 的插件二进制、脚本、市场、账号或云端数据。

## 4. 所有权原则

以下能力必须内置：高频每键查询、需要深度 OS API、含隐私核心数据、或必须满足极低延迟的能力。应用、文件、剪贴板、窗口、系统命令、计算器、Quicklinks 和 Snippets 因此属于宿主 Provider。

以下能力适合作为官方插件：网络型、表单型、纯转换型、可以独立更新且不应扩大宿主权限面的能力。翻译和开发者工具因此使用官方 WASM 插件。

插件搜索只暴露静态命令入口；用户执行命令后才启动 `novahub-plugin-host`。这保证输入过程不会因插件冷启动或网络访问抖动。

## 5. 现代化体验架构

### 5.1 Command Center

- 统一混排应用、命令、文件、计算结果、Quicklinks、Snippets 与插件入口。
- 查询首字符可进入过滤器：`>` 命令、`/` 文件、`@` 插件；过滤器必须可见、可移除，不能依赖记忆。
- 左侧结果流保持键盘选择，右侧 Preview 只在内容确有价值且宽度允许时出现。
- `Ctrl/Cmd + K` 打开 Action Panel，Enter 的主动作在结果存续期间保持稳定。
- 使用稳定 ID、流式首批结果和虚拟列表，异步结果不抢走选择。

### 5.2 Clipboard Studio

- 以时间分组展示文本、图片和文件，支持类型筛选、固定与全文搜索。
- 预览区明确内容来源应用、采集时间、敏感状态与可执行动作。
- 密码管理器、隐私窗口和用户排除应用默认不记录；敏感项不生成内容预览。
- 清空流程说明范围并可选择“全部”或“未固定项”；清理成功以非抢焦点 Toast 反馈。

### 5.3 File Explorer Search

- 搜索框下方使用紧凑过滤条表达类型、目录和修改时间。
- 结果行显示名称、路径、类型、大小与时间；Preview 支持文本、图片和基础元数据。
- 系统索引不可用时展示明确降级状态和修复入口，不执行隐式全盘扫描。

### 5.4 Quicklinks 与 Snippets

- Quicklink 支持可命名参数、默认值与 URL 编码预览。
- Snippet 支持日期、剪贴板、光标位置等宿主管理变量，不执行任意脚本。
- 首次执行参数化项目时打开紧凑 FormView；参数齐全时直接执行。

### 5.5 Window Manager

- 用不超过 3 × 3 的可视化布局网格表达位置；同时提供可读动作名称和快捷键。
- 显示器切换、窗口移动和尺寸调整均可纯键盘完成。
- 不支持调整的窗口给出原因，不静默失败；macOS 首次使用说明辅助功能授权。

### 5.6 Developer Toolkit

- JSON、编码、Hash、UUID、颜色和二维码共享“双面板工具”模板：左侧输入，右侧结果与诊断。
- 工具切换使用标签或命令菜单，不堆叠多个嵌套卡片。
- 大输入提供进度、取消与大小上限；复制后保持焦点和滚动位置。

### 5.7 Extension Gallery

- 已安装与可发现插件使用标签切换，列表优先展示名称、发布者、用途、权限摘要和兼容版本。
- 安装前先展示权限差异；更新增加权限时必须重新确认。
- 卸载默认删除代码、设置、缓存、凭据、权限和插件数据；外部文件与远端数据明确排除。

### 5.8 Migration Center

- 导入 uTools/Raycast 导出的配置、Quicklinks、Snippets 与插件清单，不读取其凭据或执行代码。
- 扫描结果分为“可直接导入”“可映射到 NovaHub 能力”“需要重写为 WASM”三类。
- 导入前提供逐项选择和冲突预览；导入以事务执行，失败可回滚并导出报告。
- 开发者迁移报告将常见 UI/权限概念映射到 WIT 与官方 View，并链接 Rust SDK 示例。

Figma Starter 继续使用三页结构：`00 Foundations`、`01 Components`、`02 Prototype`。现有 10 个画板保留，新增画板作为 `02 Prototype` 内的分区，不增加页面数。

## 7. 视觉与交互语言

- 风格为高密度、低干扰、键盘优先的桌面工作台；避免营销式 Hero、大面积渐变、装饰光斑和卡片套卡片。
- 使用 Nova 品牌的蓝色作为焦点色，绿色、琥珀和红色表达状态，保持非单一色相。
- 启动器容器最大圆角 8 px；弹层模糊只用于背景退让，不作为装饰。
- 功能图标统一使用 Lucide 风格，品牌图标仅用于产品身份；图标按钮有 Tooltip 和无障碍名称。
- 动效 120–180 ms，仅使用 opacity/transform；首帧反馈不晚于 100 ms，系统减少动画时移除位移。
- 普通文本对比度至少 4.5:1；焦点环 2 px；桌面图标按钮命中区域至少 36 px，关键确认按钮高度至少 36 px。
- 支持键盘全流程、UI Automation/NSAccessibility、200% 文本缩放、深浅主题、高对比度与输入法组合态。

## 8. 迁移兼容边界

V1 可以导入：Quicklinks、Snippets、别名、用户选择的设置和插件清单中可公开解析的字段。导入器必须由用户显式选择文件，并在本地处理。

V1 不导入：账号令牌、插件凭据、剪贴板历史、云端数据、未公开数据库、任意脚本及插件可执行代码。Raycast Extension 和 uTools 插件必须重写为 `.novahub-plugin`；迁移工具只生成差异报告、模板和字段映射。

## 9. 分阶段交付

1. **P0 技术探针（2–3 周）**：Slint 启动器、全局快捷键、流式搜索、WIT 跨进程、Windows/macOS 平台探针和性能基线。
2. **P1 Windows Alpha（6–8 周）**：8 个内置 Provider、插件生命周期、Clipboard/File/Window 主流程和 P0 原型。
3. **P2 工具与迁移 Beta（5–7 周）**：6 个官方插件/工具族、Gallery、Migration Center、SDK 与导入事务。
4. **P3 双平台 Release Candidate（4–6 周）**：macOS 核心能力补齐、无障碍、签名更新、性能与稳定性硬化。

周期按 3–5 名有 Rust/桌面经验的工程师估算；单人实施应按依赖顺序推进，不应把周数理解为承诺日期。每阶段必须通过退出条件后才能扩大范围。

## 10. V1 验收

- Windows 完成 14 项能力的表格主流程；macOS 完成标记为“完整/核心”的范围。
- 从快捷键到热首帧 P95 不超过 100 ms，输入到首批本地结果 P95 不超过 50 ms，宿主闲置 RSS P95 不超过 70 MiB。
- 插件 Host 只在执行插件命令时启动，空闲回收；插件崩溃、超时或超限不影响内置能力。
- uTools/Raycast 导入样例能生成确定性分类报告；测试证明不执行导入内容且失败可回滚。
- P0/P1/P2 原型状态具备确定性入口，在浅色、深色、200% 文本与减少动画下无重叠或关键内容丢失。
- Windows Narrator 与 macOS VoiceOver 能完成唤起、选择、执行、返回、安装权限审阅和卸载确认。

## 11. 非目标与演进触发器

V1 不包含直接插件兼容、Linux、移动端、任意 WebView、JavaScript 运行时、常驻第三方插件、AI 代理、账号同步或团队市场。

只有当至少 20 个真实迁移需求中有 30% 无法由官方组件表达，且独立 WebView Host 的内存与隔离预算得到实测验证时，才评审受限 WebView。只有当 macOS 核心能力达到同一稳定性门槛后，才承诺功能完全对齐。
