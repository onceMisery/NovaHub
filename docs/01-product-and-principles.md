# NovaHub 产品定位与设计原则

## 1. 产品定义

NovaHub 是一个本地优先的桌面行动入口。用户通过一个全局快捷键唤起它，以统一搜索和命令界面完成应用启动、信息查找、快速计算、剪贴板调用、系统操作与插件任务。

NovaHub 不只是应用启动器。它的长期价值是把分散的桌面能力收敛成一套可搜索、可组合、可授权、可观察的行动协议。

中文名“星汇”表达两层含义：每个命令或插件是独立能力节点，NovaHub 负责把这些节点汇聚成统一入口；同时保留新星、探索和扩展的品牌联想。

### 品牌图标

品牌标记由三颗能力星、三条汇入轨迹和一颗中心 Nova 组成。三颗小星代表内置能力、第三方插件和用户工作流，轨迹表达“汇”，中心四角星表达新星爆发与统一行动入口。

- 彩色 App Icon 使用深色中性底、蓝色汇聚轨迹与绿/黄/红能力节点，避免单一蓝紫色调。
- 透明品牌标记用于应用标题栏、设置和文档；单色标记用于菜单栏、系统托盘和高对比度模式。
- 16–32 px 时只保留主几何，不附加字母、文字或细碎星芒；轮廓必须在深浅背景上保持可辨识。
- 图标资产位于 `assets/brand/`，实现端从同一 SVG 源生成 Windows ICO、macOS ICNS 和发布所需 PNG 尺寸。

## 2. 目标用户

- 高频使用键盘的开发者、设计师、运营人员和知识工作者
- 希望减少鼠标切换、窗口寻找和重复操作的桌面用户
- 需要扩展工具能力，但不愿为每个小工具安装常驻应用的用户
- 重视本地数据、可控权限和资源占用的高级用户

## 3. 要解决的问题

- 桌面能力分散在应用、菜单栏、系统设置、网页和脚本中
- 常见工具使用 Electron 或常驻后台服务，闲置资源成本偏高
- 插件拥有过多系统权限，安装和卸载边界不清晰
- 第三方 UI 各自为政，导致交互、主题、键盘导航和可访问性不稳定
- Windows 与 macOS 的能力差异常被泄漏给插件作者

## 4. 产品原则

### 即刻响应

快捷键唤起、输入和选择必须保持可预测的低延迟。任何网络、磁盘、插件或图片任务都不得阻塞 UI 线程。

### 本地优先

默认不要求账号，不上传查询、剪贴板或文件元数据。联网能力只能由用户主动启用的功能或已授权插件使用。

### 宿主保持稳定

第三方代码永远不进入主 UI 进程。插件失败可以降级或重启，不能破坏启动器、内置能力和数据管理。

### 能力默认拒绝

插件不能获得环境变量、任意文件、任意网络、进程启动或后台常驻能力。所有系统能力通过可审计的 capability 授权。

### 一致而非无限自由

插件使用官方声明式 UI。宿主拥有视觉令牌、渲染、焦点、键盘导航、可访问性和主题，插件拥有内容、状态和业务行为。

### 删除应当完整

禁用与卸载是两个不同操作。卸载默认删除插件代码、数据、凭据、缓存、索引和权限；外部文件和远端数据不承诺自动撤销。

## 5. 统一术语

| 术语 | 定义 | 避免使用 |
|---|---|---|
| 命令 | 可被搜索并由用户主动执行的最小能力入口 | 功能点、菜单项混用 |
| 提供器 | 向主搜索返回候选结果的内置模块 | 插件，除非确实是第三方插件 |
| 插件包 | 作为整体安装、更新、禁用和卸载的版本化单元 | 前端插件、后端插件两个独立产品 |
| 插件会话 | 用户打开某个插件命令后，到退出该视图前的短生命周期实例 | 后台服务 |
| 官方视图 | 插件通过协议返回、由宿主渲染的受限 UI 模型 | 网页、DOM |
| 能力 | 宿主授予插件的受控系统操作权限 | 原生权限、无限权限 |
| Plugin Host | 按需启动并承载 Wasmtime 的独立进程 | 插件本身 |

## 6. MVP 非目标

- Linux、移动端和浏览器端
- 账号、云同步、团队策略和插件市场
- TypeScript/JavaScript 插件
- 任意 HTML、WebView 或原生动态库插件
- 第三方插件的定时任务、常驻后台与全局事件监听
- 工作流编排、AI 代理和远程控制

这些能力可以出现在长期路线中，但不能反向污染 MVP 的协议和资源模型。
