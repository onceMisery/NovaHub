# NovaHub 路线图、项目展望与最终形态

## 1. 路线图原则

每个阶段都必须先验证上一阶段的核心假设，再扩大自由度。插件 API、权限和数据删除语义属于长期契约，优先稳定；市场、账号和云同步属于产品增长层，不能倒置优先级。

## 2. Phase 0：设计与技术探针

目标：用最少代码验证最危险的技术假设。

- Slint 无边框启动器、快捷键和窗口定位探针
- Wasmtime Component Model + WIT 的真实跨进程调用
- Windows/macOS 上应用发现、Spotlight/Windows Search、凭据存储探针
- View 模型到 Slint 模型的渲染快照
- SQLite 加密载荷、迁移和插件命名空间探针

退出条件：两平台都能完成快捷键 → 搜索 → 打开内置命令；一个 WASM 示例能在 Host 崩溃和超时后恢复；性能预算有真实基线。

## 3. Phase 1：可用 MVP

目标：日常可用且有可开发的插件体验。

- 应用启动、计算器、剪贴板历史、基础文件搜索、系统命令
- 插件安装、禁用、原子更新、卸载和默认数据删除
- Rust SDK、CLI、Mock Host 和两个示例插件
- 官方声明式 List/Grid/Detail/Form/ActionPanel
- Windows/macOS 签名测试版

退出条件：MVP 验收表全部有测试证据；至少 5 名内部用户连续一周使用；没有 UI 主线程阻塞和高优先级数据删除缺陷。

## 4. Phase 2：插件生态基础

- 插件开发文档站、模板、示例和本地调试器
- 插件包静态分析、签名发布、权限审核和撤销列表
- 插件详情、变更日志、兼容 API 版本显示
- 更好的资源句柄、分页和离线缓存
- 可选的 TypeScript SDK 适配器原型，但仍使用同一 WIT 语义

退出条件：第三方作者无需阅读宿主源码即可完成插件；插件安装失败和权限拒绝可解释；协议一致性测试覆盖 Rust 与 TypeScript 适配器。

## 5. Phase 3：工作流与组合能力

- 用户把多个命令串成有类型输入/输出的本地工作流
- Action Graph 只组合已授权 capability，不允许任意脚本执行
- 插件可声明结果类型、输入类型和可取消步骤
- 本地模板与导入导出，不默认云同步
- 面向批量任务的可见进度、撤销和失败恢复

退出条件：工作流不会变成隐式常驻后台；每一步都能审计、取消和重放；单步插件权限不被组合器扩大。

## 6. Phase 4：可选云服务与团队能力

只有本地优先产品已经稳定后才评估：

- 用户主动开启的设置/工作流同步
- 端到端加密的个人配置同步
- 团队插件白名单、策略和私有分发
- 企业代理、离线镜像和审计导出

云端只同步明确允许的数据，不承载插件执行，不保存剪贴板正文和原始查询。关闭云服务后本地核心功能必须完整可用。

## 7. 最终形态

NovaHub 的最终形态不是“另一个带插件的启动器”，而是一个本地能力操作系统：

```text
统一召唤层：全局快捷键、自然语言/关键词、上下文入口
        ↓
能力目录：内置提供器、第三方命令、类型化 Action Graph
        ↓
统一体验层：官方 View、主题、焦点、无障碍、资源和错误语义
        ↓
安全执行层：WIT capability、WASM 隔离、可取消、可观测、可撤销
        ↓
本地数据层：搜索、剪贴板、凭据、插件命名空间与迁移
        ↓
可选协作层：签名市场、私有插件、策略同步和端到端加密配置
```

最终用户感知到的是一个轻量、稳定、可预测的入口：打开应用、搜索文件、处理剪贴板和运行插件都遵循同一套键盘与反馈规律；开发者感知到的是一个有明确类型、权限和生命周期的能力平台；企业感知到的是可签名、可撤销、可审计而不依赖云端执行的桌面基础设施。

## 8. 长期产品展望

### 对用户

从“找到东西”扩展为“完成动作”：搜索结果不仅打开目标，还能接收输入、预览结果、确认副作用和撤销动作。

### 对开发者

从“写一个命令”扩展为“发布一个可组合能力”：SDK 提供类型化输入输出、快照测试、权限模拟、性能预算和兼容迁移。

### 对平台

从“插件运行时”扩展为“本地能力协议”：同一 WIT 语义可被 Rust、TypeScript 和未来其他语言适配，但宿主永远保留渲染和权限所有权。

### 对生态

从“下载插件”扩展为“可信能力目录”：每个插件有签名、权限说明、版本兼容、变更日志、撤销状态和用户可见的数据删除语义。

## 9. 明确不追求的最终形态

- 不追求用 Web 技术重做所有原生体验
- 不追求让插件拥有主窗口 DOM 或任意系统权限
- 不追求通过常驻 AI/后台代理制造功能粘性
- 不追求把所有数据上传到云端再换取跨设备体验
- 不追求兼容没有真实用户的旧协议分支

## 10. 方向性风险与触发器

| 风险 | 触发器 | 行动 |
|---|---|---|
| Slint 关键无障碍能力不足 | 核心流程无法通过平台辅助技术 | 评估原生控件适配或 Tauri 作为局部替代，不先混用两套主 UI |
| 共享 Host 隔离不足 | 可复现的跨插件影响 | 迁移到高风险插件独立进程并量化内存代价 |
| 系统搜索质量不足 | 参考数据集 P95 超时或召回不达标 | 增加受控索引，不直接引入无界全盘扫描 |
| 官方组件无法覆盖高价值场景 | 3 个以上真实插件需要复杂编辑器 | 评审独立 WebView Host，保持核心组件协议不变 |
| 生态审核成本过高 | 人工审核成为发布瓶颈 | 自动静态分析、权限分级和可信发布者策略，保留撤销能力 |
