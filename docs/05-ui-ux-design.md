# NovaHub UI/UX 与官方组件系统

## 1. 体验方向

NovaHub 是高频操作工具，不是营销页面。视觉应安静、清晰、可扫描：搜索是第一视觉焦点，结果信息密度高但层级明确，装饰不与任务竞争。避免大标题、卡片套卡片、渐变背景、玻璃拟态泛滥、胶囊按钮堆叠和单一紫蓝色调。

## 2. 主窗口

### 启动器窗口

- 默认内容宽度 720 px，最大高度 560 px；根据系统缩放使用逻辑像素
- 顶部搜索区域高度 64 px，结果列表行高 56 px，底部动作栏 40 px
- 窗口位于当前活动显示器可用区域的水平中心、上方约 18%
- 空查询显示最近使用、固定命令和少量建议，不显示教学型大段说明
- 结果增多时只增长到最大高度，之后列表虚拟滚动，窗口不因异步结果跳动
- 轻圆角建议 8 px；阴影仅用于区分浮层与桌面，不使用厚重彩色光晕

### 设置与插件管理窗口

- 使用常规可调整大小的桌面窗口，最小尺寸 920 × 640 px
- 左侧一级导航宽 220 px，右侧内容使用单一滚动区域
- 页面段落不包装成悬浮大卡片；仅插件列表项和明确工具面板使用边框容器

## 3. 信息结构

主搜索结果分为应用、命令、文件、计算和插件等语义类型，但默认使用统一排序流。只有当用户输入显式筛选前缀时才进入单提供器视图。

每个结果行固定包含：

- 32 px 图标或缩略图槽
- 主标题，单行优先，溢出时省略并提供完整可访问名称
- 可选副标题，不抢占主标题对比度
- 右侧类型、快捷键或状态附件
- 整行主动作与选中状态

动作面板由 `Cmd/Ctrl + K` 打开，列出当前项的主次动作。Enter 永远对应可预测的主动作，不因异步响应改变。

## 4. 视觉令牌

### 颜色

使用语义令牌，Slint 组件中禁止直接硬编码颜色。推荐初始基线：

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `surface.canvas` | `#F4F5F7` | `#151719` | 普通窗口背景 |
| `surface.elevated` | `#FFFFFF` | `#202327` | 启动器与浮层 |
| `surface.selected` | `#E8F1FF` | `#25364F` | 当前结果 |
| `text.primary` | `#17191C` | `#F5F7FA` | 主文本 |
| `text.secondary` | `#5E6670` | `#AEB5BF` | 副文本 |
| `border.subtle` | `#DCE0E5` | `#373C43` | 分隔线 |
| `accent.primary` | `#1769E0` | `#6EA8FF` | 焦点和主动作 |
| `status.success` | `#168553` | `#57C995` | 成功 |
| `status.warning` | `#A45A00` | `#F2B35B` | 警告 |
| `status.danger` | `#C43131` | `#FF7B7B` | 错误与删除 |

主色使用蓝色，状态使用绿、黄、红，使界面不是单一色相。正常文本对比度至少 4.5:1，大图标和边界至少 3:1；浅色与深色模式分别测量。

### 字体

- Windows 使用 Segoe UI Variable，macOS 使用 SF Pro/System Font
- 插件不能选择字体
- 字号层级：12/13/14/16/20 px，避免在紧凑面板使用展示级字号
- 正文常规 400，标签 500，标题 600；不使用负字距
- 数字状态与快捷键可使用系统等宽字体或 tabular figures
- 支持系统文本缩放；组件高度可增长，不以截断替代可访问性

### 间距、尺寸与圆角

- 以 4 px 为基本单位，常用间距 4/8/12/16/24/32
- 图标规格 16/20/24/32 px，统一轮廓风格和视觉粗细
- NovaHub 品牌图标采用“三星汇聚成 Nova”语义；产品标记与功能图标分离，功能图标继续使用统一的 Lucide 风格轮廓
- 图标按钮视觉尺寸至少 28 px、点击区域至少 36 px；不熟悉图标必须有 Tooltip 和可访问名称
- 输入、按钮和列表尺寸必须稳定，加载、悬停和状态文字不得改变布局尺寸
- 控件圆角 6 px，容器最多 8 px；不用大面积胶囊造型

## 5. 交互和键盘

| 按键 | 主界面行为 |
|---|---|
| `↑` / `↓` | 移动结果选择 |
| `Enter` | 执行主动作 |
| `Cmd/Ctrl + K` | 打开动作面板 |
| `Cmd/Ctrl + P` | 切换提供器/筛选 |
| `Tab` / `Shift+Tab` | 在表单与动作间移动焦点 |
| `Escape` | 关闭动作面板、返回上级、最后隐藏窗口 |
| `Cmd/Ctrl + ,` | 打开设置 |

- 焦点环始终可见，不因鼠标使用而永久移除
- 选中与焦点是不同状态，但在列表键盘导航时可以共同呈现
- 鼠标悬停不能成为唯一入口；所有操作有键盘路径
- 异步动作在 100 ms 内提供反馈，超过 300 ms 显示轻量进度，超过 2 秒给出可取消或重试路径
- 动画使用 120–180 ms 的 opacity/transform，表达出现、返回和选择关系；系统减少动画时关闭位移动画

## 6. 官方组件语义

### ListView

固定行模型、分区标题、空态和游标分页。超过 50 项必须虚拟化。更新必须按稳定 ID 保持选择与滚动位置。

### GridView

使用宿主决定的列数和最小单元宽度。资源占位必须保留尺寸，图片异步加载不能造成布局跳动。

### DetailView

正文宽度限制在可读范围。Markdown 标题层级连续，链接须明确可聚焦；代码块可横向滚动，但整个页面不横向滚动。

### FormView

字段使用可见标签，Placeholder 不代替标签。错误紧邻字段并说明原因与修复方式；提交失败聚焦第一个错误。密码字段支持显示/隐藏但默认遮蔽。

### ActionPanel

动作按主动作、上下文动作和危险动作分组。危险动作使用文字、图标和危险色共同表达；不可只靠红色。插件卸载等不可逆操作必须确认。

### Toast 与错误视图

Toast 不抢焦点，3–5 秒自动消失且可被屏幕阅读器礼貌播报。错误必须包含恢复动作；不能只显示“发生错误”。

## 7. 启动器状态

- Idle：最近与固定项
- Searching：立即保留现有骨架，首批结果到达后替换；不全屏转圈
- Empty：说明未找到，提供清除筛选或打开文件搜索设置
- Partial：某提供器失败时展示局部状态，不覆盖其他结果
- Plugin Loading：显示插件名、取消入口，避免空白页面
- Permission Prompt：说明为何需要、允许范围和拒绝后的影响
- Destructive Confirm：明确对象、删除范围和不可恢复性

## 8. 跨平台一致与适配

信息架构、组件语义和快捷键意图一致；修饰键、窗口材质、系统菜单、滚动条、文件选择器和凭据提示适配平台习惯。macOS 使用 Cmd，Windows 使用 Ctrl；不要在界面里硬编码同一按键字符串。

输入法组合期间不得触发中间搜索提交或快捷键冲突。窗口在多显示器、不同 DPI、全屏应用和虚拟桌面中均需正确定位与恢复焦点。

## 9. 无障碍验收

- Windows 使用 UI Automation，macOS 使用 NSAccessibility 映射 Slint 语义
- 主窗口可完全通过键盘操作，焦点顺序等同视觉顺序
- 所有图标、图片、列表项、状态和表单控件拥有名称、角色和值
- 颜色不是唯一状态表达
- 200% 文本缩放下没有文字重叠、按钮溢出或关键内容丢失
- Windows Narrator 与 macOS VoiceOver 执行核心流程
- 高对比度、减少动画和深浅色模式分别验证

## 10. Figma 原型范围

原型以本规范为权威，至少包括：

1. 主启动器：空查询/搜索结果与动作提示
2. 插件官方视图：翻译插件 FormView + 结果区
3. 插件管理：已安装列表、详情、权限和卸载确认

原型不是任意视觉探索，必须使用相同的色彩、间距、字体、圆角和组件语义，以便后续映射为 Slint 组件。
