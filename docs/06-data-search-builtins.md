# NovaHub 数据、搜索与内置能力

## 1. 数据原则

NovaHub 的核心数据属于本机当前用户。数据库只保存结构化元数据和必要内容；密钥放在系统凭据存储，大文件和图片使用受预算约束的文件缓存。插件永远不获得数据库连接。

## 2. SQLite 划分

建议单一主库、明确表所有权：

- `settings`：版本化设置键值
- `commands`：内置与插件静态命令注册
- `usage_events`：有限窗口的执行次数与最近时间，不保存原始查询全文
- `favorites`：用户固定与别名
- `clipboard_items`：加密载荷引用、类型、时间与过期策略
- `plugin_installations`：版本、状态、active 路径、API 范围
- `plugin_permissions`：用户批准的 capability 快照
- `plugin_storage`：`plugin_id + key` 命名空间与配额
- `pending_deletes`：等待重试的本地删除任务

启用外键、WAL 和 `busy_timeout`。迁移包含 schema 版本、事务和回滚测试；禁止插件定义主库迁移。

## 3. 敏感数据

- 剪贴板载荷使用每台设备生成的主密钥加密
- 主密钥存于 Windows Credential Manager 或 macOS Keychain
- 插件 Token 以插件 ID + 服务名隔离存储，数据库仅保存不敏感引用
- 日志不记录剪贴板正文、查询全文、文件内容、Token 或 HTTP Body
- “清空剪贴板”和“卸载插件”同步删除数据记录、缓存和凭据引用

普通文件系统删除不等同于安全擦除，产品不得承诺 SSD 上的不可恢复擦除。

## 4. 搜索管线

```text
Query
→ Normalize（大小写、Unicode、路径、拼音可选）
→ Providers 并发获取候选
→ Nucleo 模糊匹配
→ 类型先验 + 固定项 + 最近/频率信号
→ 稳定排序与分批发布
```

建议基础评分：文本匹配 60%，类型上下文 15%，用户固定 15%，最近/频率 10%。权重需通过基准与用户测试调整，不在代码中散落魔数。

首帧前只读取唤起所需设置和最小命令快照；SQLite 全量读取、学习信号加载和文件预览在首帧后执行。命令搜索使用宿主复用的低层 `nucleo-matcher` scratch，不维护常驻索引或线程池；未就绪时返回明确的 loading/partial 状态，禁止在每次按键时重建匹配器。

隐私边界：MVP 的学习信号完全本地，不构建用户画像，不将原始查询发给插件。插件命令只作为静态候选参与主搜索；用户打开命令后，输入才进入插件会话。

## 5. 应用提供器

- Windows 读取开始菜单、应用注册和必要图标；避免枚举整个磁盘
- macOS 使用 LaunchServices/NSWorkspace 获取应用清单
- 索引记录名称、路径/Bundle ID、图标缓存键、别名和更新时间
- 监听平台支持的变更信号，低频兜底重建
- MVP 宿主先采用最多 128 条的惰性应用快照；搜索按键只在快照内过滤，启动时加载一次，之后由宿主每 30 秒低频刷新，应用变更时也可显式刷新快照
- 启动失败展示具体原因和修复入口，失效记录延迟清理

## 6. 文件提供器

- Windows Search 与 Spotlight 是首选 canonical source
- 查询带最大结果数、超时和取消令牌
- 文件候选只保存展示所需元数据，不复制内容
- 用户显式选择“打开所在目录”时再解析平台动作
- Windows Search/Spotlight 不可用、索引关闭、权限不足或数据库损坏时返回明确的“文件搜索不可用”状态和平台指导；不得伪装成空结果
- MVP 不以递归扫描作为隐式 fallback。Windows `where.exe` 递归扫描和 macOS 应用目录扫描只可由诊断/高级设置显式开启，并且仍受结果数、取消和超时约束

## 7. 剪贴板提供器

- 监听属于内置平台服务，可以随主程序常驻
- 文本做内容哈希去重；相邻重复只更新时间
- 图片压缩并设单项、总量上限；超过上限仅保留类型提示或拒绝记录
- 宿主 `ClipboardVault` 默认保留 500 条最近最少使用记录；设置可在受限范围内调整数量和 TTL。读取会提升到队首，启动和每次列表读取都清理过期项
- `clipboard.history` 打开按需 `ClipboardWindow`；窗口只展示固定 8 条元数据槽位，支持文本/图片筛选、显式预览、文本复制、固定/取消固定、暂停和清空。图片无法安全解码时必须展示明确状态，不伪造预览成功。
- Shell 提供 `clipboard`、`clipboard capture`、`clipboard pause`、`clipboard resume` 和 `clipboard clear` 宿主命令；轮询/监听器只能调用同一捕获入口，不得绕过暂停、去重和加密策略
- 文本最多 1 MiB，图片最多 8 MiB；密文载荷不进入 SQLite 正文表，SQLite 只记录类型、摘要、创建时间和过期时间
- 加密密钥只通过 `CredentialStore` 抽象取得；Windows Credential Manager/macOS Keychain 由平台适配器提供，其他平台或读取失败时能力表必须报告不可用并拒绝捕获
- 忽略 NovaHub 自己恢复到剪贴板产生的回环事件
- 默认排除已知密码管理器和用户配置的敏感来源；平台提供可靠的敏感/临时标记时作为附加信号，不能把不存在的平台标记当成唯一保护
- 默认 7 天/500 条，到期与超限按最旧未固定项优先清理；固定项由用户明确保留，策略仍由宿主校验并持久化，不能扩大资源预算

## 8. 计算器与系统命令

计算器使用明确语法解析器和确定性数值库，禁止 `eval`。单位和货币换算分开：离线单位换算可进 MVP，实时汇率需要可见的数据来源、更新时间和网络策略。

系统命令采用平台能力表注册，不允许插件伪装为系统命令。破坏性命令必须由宿主确认，确认不可由插件自绘。

## 9. 缓存预算

| 缓存 | 初始预算 |
|---|---:|
| 应用图标内存缓存 | 16 MiB |
| 插件/详情图片内存缓存 | 32 MiB |
| 磁盘资源缓存 | 256 MiB（磁盘） |
| 插件编译缓存 | 512 MiB（磁盘），按 LRU 清理 |
| 日志 | 5 × 5 MiB 滚动 |

预算是默认值，需要压测后调整。达到限制时应清理可再生数据，不删除用户数据。

## 10. 数据导出与恢复

MVP 支持导出非敏感设置、固定项和插件清单，不默认导出剪贴板与插件凭据。恢复时先校验版本和内容，插件数据只有在对应插件已安装且用户确认后导入。数据库损坏时保留原文件副本，重建可再生索引并尽可能导入设置。
